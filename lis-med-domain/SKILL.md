# Предметная область ЛИС (медицинская генетика)

Ты работаешь не с абстрактными числами: результат уходит врачу-генетику и в историю пациента.
Ошибка в расчёте — это не «баг», а неверное заключение.

## Что считает система

1. **Идентификация / родство** — вероятности гипотез по наборам STR-локусов, отношения правдоподобия (LR),
   PI (paternity index) по локусу, CPI (combined paternity index), вероятность родства (W).
2. **Популяционные частоты** — аллельные частоты по локусам и субпопуляциям; мутации (paternally/maternally
   transmitted), учёт несовпадений (exclusions), пороги «мутация vs исключение».
3. **Смеси и неполные профили** — вклад участников, drop-in/drop-out, пики-артефакты.
4. **Интерпретация вариантов** (для NGS-части) — классификация по ACMG/AMP, population frequency,
   in-silico предикторы, клиническая значимость.

## Правила, которые нельзя нарушать

1. **Формулы — по литературе, а не «по логике».** Любая формула в коде сопровождается ссылкой:
   источник (ISFG recommendations, книги/статьи, версия), и указанием, какие допущения приняты.
2. **ISFG-рекомендации — база.** Для STR-расчётов: рекомендации ISFG по мутациям, порогам, минимальному
   числу локусов. Ссылка на конкретную публикацию, а не «так принято».
3. **Популяционные данные — с источником и версией.** Частоты аллелей: откуда база, какая субпопуляция,
   какой релиз. Не смешивать популяции без явного решения и записи в отчёте.
4. **Округления и точность** — фиксировать (сколько знаков, где округляется, в каком типе хранится).
   Расхождение на 1e-9 между версиями — это нормально; расхождение в 3-м знаке вероятности — нет,
   его надо объяснить.
5. **Отрицательный результат — тоже результат.** «Исключение отцовства» должно быть обосновано числом
   несовпадений и LR, а не одним флагом.
6. **Ничего не выдумывать про пациента.** Тестовые данные — только из стенда. В отчётах и карточках
   реальные ФИО/номера заказов не публиковать.
7. **Медицинский текст** — без диагнозов от себя: формулировки про вероятность и совместимость,
   а не «ребёнок является сыном». Юридическую формулировку задаёт шаблон/эксперт.

## Проверки перед сдачей расчёта

- есть эталонный пример (заказ из стенда/истории) и результат совпадает с ожидаемым;
- граничные случаи: 0 локусов, 1 локус, все гомозиготы, отсутствующий локус, дубликат;
- единицы измерения и типы (Double vs Currency) не теряют точность;
- в тестах есть хотя бы один реальный набор из стенда (обезличенный).
