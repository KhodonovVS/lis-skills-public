Подсистема `Registr` (прод-стек — Delphi 10.3 Rio, `Studio\20.0`): бланк заключения на N участников
(3–5 и больше), выбор метода, тексты выводов, экспорт PDF/DOCX через FastReport. Старая форма
(`SelectSamples`) остаётся рабочей — новая линия строится рядом, отдельными модулями.

## Методы расчёта × роли участников

Число участников задаёт **метод**, а не заказ: метод требует конкретных ролей, и расчёт возможен только когда
состав заказа этим ролям соответствует. «Посчитать по пяти участникам» само по себе — не метод.

| Метод | Участников | Роли |
|---|---|---|
| дуэт (F2) | 2 | ребёнок + предполагаемый родитель |
| трио (F3) | 3 | ребёнок + мать + отец |
| сиблинги (FS) | 2…n | двое и более детей одних родителей |
| полусиблинги (HS) | 3 | ребёнок + сиблинг + общий родитель |
| дед/бабка + ребёнок (GF) | 2 | ребёнок + родитель предполагаемого отца |
| дядя/тётя + ребёнок (AVU) | 2 | ребёнок + сиблинг предполагаемого родителя |
| две пары | 4 | ребёнок₁+родитель₁, ребёнок₂+родитель₂ |
| сложное родство | 5 | ребёнок + мать + предполагаемый отец + сиблинг + бабушка |

Информативность растёт от **независимых** ролей, а не от числа людей: пятый участник той же материнской линии
добавляет меньше, чем один сиблинг по другому отцу. Разрешать «выделить любых N и нажать Рассчитать» нельзя —
перепутанные роли дают правдоподобный, но ложный PI, а это дискредитация заключения.

Правило доступности и справка живут в данных, не в коде:

```
ConclRole        Code, Caption, IsActive      -- child, mother, father, sibling, half_sibling,
                                                 grandparent, uncle_aunt
ConclMethod      Code, Caption, ParentCode, SortOrder, MinParticipants, MaxParticipants,
                 IsActive, HelpRtf, HelpVersion
ConclMethodRole  MethodCode, RoleCode, IsRequired, MinCount, MaxCount, SortOrder
```

Плюс маппинг существующего справочника `Relationship` → `ConclRole`. Доступность метода считается запросом по
составу заказа: на каждую роль с `IsRequired = true` должен найтись участник, количество — в `MinCount..MaxCount`.
Причина недоступности короткая и конкретная («нет роли «мать»», «нужно 3 участника, в заказе 2»), а не
общее «метод недоступен».

UI-правила (BOSS спрашивал отдельно):

- недоступный метод **виден**, но серым, с причиной в строке; скрывать его — ошибка, эксперт не поймёт,
  почему пропал привычный метод;
- рядом с методом — кнопка справки: роли, что метод доказывает и что не доказывает, формула LR/PI, ограничения
  (мутации, нулли-аллели, инбридинг), ссылка на ISFG; текст берётся из `ConclMethod.HelpRtf`, а не из `.pas` —
  формулировки в заключении эксперт должен править без пересборки;
- над списком — баннер «доступно N из M» с раскрытием причин; кнопка «Рассчитать» заблокирована, пока роли
  не сходятся;
- справочник методов и ролей **редактируется формой** (`TMethodCatalogForm` целиком в `.dfm`): грид методов,
  грид ролей выбранного метода, редактор справки, инкремент `HelpVersion`. Метод, по которому есть сохранённые
  расчёты, не удаляется — только `IsActive = false`.

Тот же принцип «данные вместо кода» распространяется на расчёт целиком: компонент на датасетах
(раздел «Бизнес-логика — компонент на датасетах» в SKILL.md), SQL в `TFDQuery` на датамодуле, результат —
в датасет и в таблицу истории (`ConclResult`: заказ, метод, субпопуляция, эксперт, PI, текст, дата) — иначе
закрыл окно, и результата расчёта не существует.

## Что проверять до слов «готово»

1. **Подключение к приложению.** `Select-String -Path <проект>\Registr\*.pas,<проект>\*.dpr -Pattern 'MG\.Concl'`.
   Пусто = форма и сервис из UI не вызываются, весь слой — библиотека без точки входа.
2. **Шаблоны на N участников.** Если в `Reports\Conclusion\` только `default_RU/EN`, то отчёт на 4–5 участников
   собрать нечем независимо от кода; нужны `Conclusion_<N>_<lang>.fr3` (альбомная ориентация, когда колонок много).
3. **Семантика текстов.** Родство выводится словами («Предполагаемый сиблинг N»), а не ФИО; CPI брать из
   готовых результатов, не пересчитывать в тексте.
4. **Сверка с эталоном.** Контрольные заказы — 153766 и 290940, по 3 / 4 / 5 участников; сравнивать собранный
   PDF с эталонными `.docx` на стенде с копией боевой БД. Без этой сверки задачу не закрывать.
