# Запись в Paperclip: `pc-note` и вопросы

MCP-инструменты для записи НЕ использовать — они упираются в approval review. Рабочий канал:

```
pc-note show CMP-27                          # статус, прогон, последние комментарии
pc-note comment CMP-27 "текст"              # комментарий (201 = записано)
pc-note status CMP-27 in_review             # todo | in_progress | in_review | done | blocked
pc-note create "Заголовок" --parent CMP-24 --assignee delphi-dev --desc-file /path/desc.md
```

Ключ и адрес CLI читает сам (`/etc/paperclip-agents.env`), `source` не нужен.

## Правила

1. Результат шага публикуется САМ, сразу: файлы, `git log`, вывод сборки (`EXIT=0`, размер exe, время),
   результат тестов (Found/Passed/Failed/Exit). Не «потом посчитаю».
2. Отчёт без артефакта не принимается: «сделал» без файла/лога/цифры — брак.
3. Если `pc-note` вернул ошибку — копировать её ТЕКСТ в карточку и продолжать остальную работу.
   «Не могу записать» без текста ошибки — запрещено.
4. Вопрос человеку — это durable interaction, а не комментарий. Задал вопрос — жди ответа,
   работу не бросай молча: фиксируй, что именно ждёшь и на каком шаге.
5. Статусы: не закрывать задачу в `done`, пока критерий приёмки не выполнен буквально
   (пример: `Tests Found 14, Passed 14, TEST_EXIT=0`). Красный тест = `in_progress` + комментарий с ошибкой.
