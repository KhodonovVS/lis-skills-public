# Ревью Delphi-кода: что искать в первую очередь

Источник: скиллы `daniele-teti/delphi-ai-skills` (Apache-2.0), адаптировано под Delphi 10.3 + FireDAC + VCL.

## Порядок ревью (не по вкусу, а по риску)

1. **Владение и время жизни** — `Free`/`try..finally`, кто владеет объектом, возвращённым из функции;
   интерфейсы и подсчёт ссылок; `TObjectList.OwnsObjects`; double free.
2. **Данные (FireDAC)** — закрыт ли `TFDQuery`, освобождён ли датасет, откатывается ли транзакция при ошибке,
   параметры типизированы (`ftGUID`, `ftFloat`, `ftDateTime`), `Prepared := True`, нет LocalSQL.
3. **Исключения** — не глотаются ли пустым `except`, освобождаются ли ресурсы при raise, `EFDDBEngineException`
   разбирается по `Errors[i]`, а не по тексту.
4. **Строки/кодировки** — ANSI/Unicode, `.dfm` в CP1251, `.pas` в UTF-8 с BOM, конкатенация SQL.
5. **Потоки** — доступ к VCL только через `TThread.Synchronize`/`Queue`, общие данные под блокировкой.
6. **API-галлюцинации** — каждый вызов, которого нет в исходниках Studio 20.0, помечать как ошибку,
   а не «стилистическое замечание».

## Формат замечания

```
[блокер|важно|мелочь] файл:строка — что не так → чем это грозит → как исправить (код)
```
Без «вроде норм» и без правок «на будущее»: только то, что реально ломает или уже сломано.
