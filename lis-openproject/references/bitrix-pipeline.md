# Конвейер «Битрикс24 → техпроект → OpenProject»

Задача класса: у BOSS много задач в Битрикс24; по каждой нужен техпроект в OpenProject — с разбором, RAW-данными, веткой в git, чек-листом и вложениями. Движок: `~/.hermes/scripts/bitrix_to_openproject.py`.

## Поток

1. Задачи, где BOSS участник: `tasks.task.list` с `filter: {MEMBER: "<uid>", CHECK_PERMISSIONS: "Y"}`; инкрементально — `>=CHANGED_DATE` от `last_sync` минус сутки запаса.
2. Чат задачи: `im.chat.get` (`ENTITY_TYPE=TASKS_TASK`) → `im.dialog.messages.get`; вложения — `result.files[]` → `disk.file.get` → `DOWNLOAD_URL` → скачать в `~/bitrix-files/<taskId>/`.
3. **RAW-архив** `~/bitrix-raw/<taskId>/`: `task.json`, `chat.txt`, `ocr.txt` и сами файлы. RAW хранить всегда, даже если модель уже отработала: BOSS разбирает спорные места по первоисточнику.
4. **OCR вложений** — обязательный шаг, а не улучшение: `tesseract <img> stdout -l rus+eng` для картинок, `pdftotext -layout` для PDF. Текст вкладывается в промпт блоком «ТЕКСТ ИЗ ВЛОЖЕНИЙ (OCR)». Уточнения по задаче часто живут только на скриншоте; без OCR модель отвечает «требует уточнения» на то, что уже написано в картинке.
5. LLM (LiteLLM `http://<адрес из окружения>/v1/chat/completions`, `DeepSeek Pro`, `temperature 0.2`) собирает разбор по фиксированной структуре.
6. OpenProject: создать или обновить WP в проекте `b24-tasks`, затем вложения и картинки в описание.
7. Состояние `~/.hermes/state/bitrix_to_op.json`: `{last_sync, project_id, wps: {b24_id: wp_id}, sigs: {b24_id: sha1(description)}}`. Без `wps` каждый прогон плодит дубли.

## Правила промпта

- Не выдумывать факты: чего нет в задаче, переписке и OCR — писать «требует уточнения».
- Номера заказов, коды образцов, ФИО, даты — дословно (в ЛИС это `MG26-290940S1T1A`, № заказа партнёра).
- BBCode чистить до подачи в модель: `[USER=…]`, `[TIMESTAMP=…]`, `[URL=…]`, `[Цитата]`, `[Вложение]`.
- Объём до 700 слов, `max_tokens` запроса 4000: на 3000 модель обрезает «Критерии приёмки / План / Открытые вопросы» и описание выглядит готовым, но половины разделов нет.
- Чек-лист собирать из «План работ» регуляркой, а не просить модель отдельно.

## Живая ветка в Forgejo

Ветка не «упоминается», а создаётся: `POST https://<домен из окружения>/api/v1/repos/<owner>/<repo>/branches` с `{"new_branch_name": "b24/<id>-<слаг>", "old_branch_name": "main"}`, заголовок `Authorization: token <pass forgejo/vlas-token>`. `201` — создана, `409/already exists` — уже была (считать успехом), иначе писать в описании «не создана: <код>».

Репозиторий выбирать по ключевым словам задачи (ehlib → `MedicalGenomics/ehlib`, graphics32, devexpress, fastreport, ems → `ems-import`, сборка/jenkins → `build-config`), по умолчанию `MedicalGenomics/medicalgenomics`. Транслит: `а→a…я→ya`, затем `[^a-z0-9]+ → -`, обрезка 40 символов **с последующим `rstrip('-')`** — иначе имя ветки кончается дефисом.

## Транслитерация

Словарь `а→a, б→b, в→v, г→g, д→d, е→e, ё→e, ж→zh, з→z, и→i, й→y, к→k, л→l, м→m, н→n, о→o, п→p, р→r, с→s, т→t, у→u, ф→f, х→h, ц→c, ч→ch, ш→sh, щ→sch, ъ→'', ы→y, ь→'', э→e, ю→yu, я→ya`.

## Надёжность разбора

- Пустой или короткий (<200 символов) ответ модели — не норма: пробовать вторую модель (`DeepSeek Flash`) и **не перезаписывать описание**, если разбор так и не получился. Иначе одна неудачная генерация стирает готовый техпроект.
- Кэш по `sha1(prompt)` в `~/.hermes/state/llm_cache/`: повторный прогон той же задачи не жжёт токены.
- Изменения фиксировать историей: при смене `sig` постить комментарий `POST /api/v3/work_packages/{id}/activities {"comment": {"raw": …}}` с последними сообщениями чата, а не молча перезаписывать описание.
- Приоритет по сроку при создании/обновлении: ≤3 дней → `priorities/9` (High), ≤7 → `8` (Normal), иначе `7` (Low).

## Триггеры

- n8n: пн-пт, 09:00/10:30/12:00/13:30/15:00/16:30/18:00 МСК (два cron-триггера: `0 9,12,15,18 * * 1-5` и `30 10,13,16 * * 1-5`), ночью и в выходные не проверять. `GET /check` → IF `tasks > 0` → `POST /run?mode=incremental`.
- Хук: `b24_op_hook.py` (systemd `b24-op-hook`, :8099, секрет `~/.hermes/secrets/b24_op_secret`), эндпоинты `GET /health`, `GET /check`, `POST /run?mode=incremental|all-open|&task=<id>`.
- Ручной: `--task <id>`, `--all-open`, `--dry-run`.
- Дайджест BOSS'у: `b24_digest.py` → `@TeremokHomeBOT` (chat 219004331), cron `5 9 * * 1-5`: просрочки, ≤3 дней, новые за сутки, задачи без техпроекта.

## Чего не делать

- Не запускать ничего в Bernstein автоматически: в описании только «что и где сделать» (репозиторий, ветка, файлы), запуск остаётся за BOSS.
- Не писать в Битрикс: доступ только на чтение, белый список методов в клиенте.
- Не гонять конвейер вне рабочих часов BOSS: ночные прогоны он считает мусором.
